# 构建 MySANY 后台表单页

产出可直接落地的表单页，遵循该后台真实的设计体系，而不是凭截图模仿。

> 本规范对齐**三一 MySANY 后台管理平台**线上真实界面，数值取自线上产物 CSS（按真实加载顺序重建层叠取最终生效声明），并与线上截图逐像素校验。
> 旧版"可信数据空间"Figma 规范（`#255CE9`、顶栏 56px、侧栏 240px、控件 40px、14px 字号、label 置顶、32px 字段节奏、64px 操作栏、大圆角、浅色外壳）**已全部作废**。

## 五条先记住

1. 深色导航壳：顶栏 `#172742`/48px，侧栏 `#1e3255`/220px，画布 `#f4f5f7`。
2. 主色 **`#29bece`**（青蓝），hover `#1995a8`。不是蓝色。
3. 表单是 **`table + colgroup` 横向布局**：**label 在左、宽 80px、右对齐、带冒号**；不是 label 置顶的纵向布局。
4. 控件高 **28px**，基准字号 **12px**，圆角 **2px**。
5. 必填 = **淡黄底 `#feffe6`**（`.is-required`），**不是红星号**。

## 工作流程

1. 用 `references/form-page-spec.md` 判定业务场景。
2. 检查目标仓库，复用其框架、组件、Token、图标、校验与路由。
3. 在写字段之前先定结构：48px 顶栏 → 220px 侧栏 → 页头 48px → 内容区 → 48px 底部操作栏。
4. 从实际业务内容推断并**只选一种**版式（单列 / 双列 / 三列 / 分组卡片 / 表格内嵌 / 锚点 / 分步）。除非用户明确要求对比工具，否则**不要渲染"规范场景"切换器或版式选择器**。
5. 每个要求的场景都要实现真实行为，不能只用文字或静态图描述交互变体。
6. 实现语义化控件、键盘焦点、必填/错误态、禁用/加载态、校验与响应式降级。
7. 对照 `references/acceptance-checklist.md` 自查；按 1440px 验收。
8. 说明有意偏离规范之处及其产品理由。

## 不可协商的规则

### 外壳
- 顶栏与侧栏为不可变基础外壳。原样复制 `[data-locked-shell="true"]` 区域与 `assets/shell/shell-lock.css`，且 `shell-lock.css` 必须**最后加载**。
- 仅允许替换可见文字。不得增删、重排、改尺寸、改配色、改选中态或替换任何外壳图标与导航项，除非用户明确要求修订基础设计标准本身。
- 菜单选中态为 **5px 实心 `#29bece` 左条 + 向右渐变至 `#29bece`**，项高 44px；侧栏搜索框底 `#425370`、高 28px。
- 图标一律用内联 SVG + `currentColor`（Material 图标名），不要用 Unicode、emoji 或第三方图标库；旧 Figma SVG 已废弃（见 `assets/shell/DEPRECATED.md`）。
- **不要渲染面包屑**——该平台用页头标题与返回按钮承担定位。

### 表单布局
- 用 `table + colgroup`：`<col style="width:80px">`（label）与 `<col>`（字段）成对重复。一行放 2 组或 3 组。
- label 用 `.s-form-label`（右对齐、自动追加冒号）；字段用 `.s-form-cell`。
- **整行字段（长文本、地址、备注、文本域）必须用 `colspan` 跨满整行**，不要把半宽控件拉伸去填补残缺的一对。
- 字段垂直节奏由 `.s-form td{padding:4px 0}` 决定（约 8px），不要改成 32px。
- 分组用 `.sany-card` + `.s-section-title`（左侧 3px 主色竖条 + 下边线）；多分组堆叠用 `.page-content-stack`，卡片间距 8px。

### 控件
- 统一 28px 高（`.s-input` / `.s-select` / `.s-field-affix`）；文本域 `.s-textarea` 最小高 60px、可纵向拉伸。
- 边框 `#d9d9d9`、hover `#4fd2db`、focus `#a6f5f5`（**focus 不加发光圈**）、禁用底 `#f5f5f5`、占位符 `#bfbfbf`。
- 圆角一律 2px（单选框与开关的 `50%` 除外）。

### 必填与校验
- 必填控件加 `.is-required`（淡黄底 `#feffe6`），**不渲染红星号**，除非业务明确要求。
- 错误态：控件加 `.is-invalid`（字色与边框 `#d50000`），并在其下渲染 `.s-msg-error`（12px `#d50000`）。
- 校验时机：提交时整体校验并聚焦第一个错误字段；已报错的字段在失焦后实时复验。
- **`备注` 在任何场景下都是可选**，不得渲染必填标记，也不得在校验中要求填写，除非后续业务规则明确覆盖此基线。

### 操作栏与按钮
- 底部操作栏 `.s-form-footer`：高 48px、右对齐、白底、上边线 `#e0e0e0`。
- 按钮顺序：次要/破坏性操作在左，**唯一强调的主按钮在最右**。
- 长表单保持底部操作栏可见。
- 每个按钮都要有可见的 hover、active/pressed 与键盘 `focus-visible` 态。
- 表格内嵌场景中，行操作必须真实增删行；锚点必须真实滚动并更新激活态；分步必须真实改变流程状态。

### 取值
- 主色 `#29bece`、hover `#1995a8`；画布 `#f4f5f7`；卡片 `#fff`；正文 `#333`；边框 `#e0e0e0`；控件边框 `#d9d9d9`；错误 `#d50000`；必填底 `#feffe6`。
- 不得引入装饰性渐变（菜单选中态除外）、大圆角、重阴影或规范中不存在的仪表盘卡片。
- 本系统**没有**统一的 success 绿 / warning 橙色板，不要自行发明。
- 不得把业务文案做成图片，必须保留真实文本与可访问的表单控件。
- 演示用的切换器只能存在于独立的 demo 外壳中，**不得**复制进可复用模板或后续生成的页面。
